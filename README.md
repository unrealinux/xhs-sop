## 第一步：生成表格

双击 `1-生成模板.bat`，得到 `选品SOP-4.0模板.xlsx`。三张表：

**初选表**（10 列 / 60 行）
`日期｜来源｜店铺名｜产品名｜竞品链接｜24小时加购｜粉丝数｜档位(自动)｜是否感兴趣｜备注`

- SOP 原话：「这一轮不设标准，只要感兴趣就行」→ 只填店铺名，档位让它自己算
- `档位` 公式：粉丝<500 → 低粉爆款；加购>800 → 大爆款；粉丝<2000 且 加购>400 → 常规爆款

**二选表**（8 列 / 60 行）
`店铺名｜产品｜笔记总数｜链接评价数｜账号权重(自动)｜拍摄能力能对齐吗｜我能超越吗｜结论(自动)`

第二轮要问自己三个问题（P19）：

| # | 问题 | 怎么判 |
|---|---|---|
| 1 | **他们的拍摄能力，我能对齐吗？** | 最基本的。他们的图比我好太多，跟了也难起来。对不齐 → 要么提升拍摄能力，要么找差异化场景 |
| 2 | **他们的账号权重高吗？** | 笔记总数>1000 且 评价数>1000 = 高权重。这种对手要用差异化运营打，**不能硬碰硬** |
| 3 | **我能超越他们吗？** | 素材能对齐 **+** 运营能力能超越 = 进调研 |

> 原话：「这个标准的核心不是这个产品好不好，而是**我能不能打得过**。」（P19）

公式：

```
账号权重 = 笔记总数>1000 且 评价数>1000  → 高权重 / 低权重
结论     = 拍摄能对齐 且 能超越          → 进调研 / 放弃
```

> 技巧：F（拍摄能对齐）填「否」时，G 不用纠结 —— 结论已经锁死「放弃」。先把 F 判完，只对 F=「是」的品去查竞品数。

**调研表**（23 列 / 60 行）—— 三张表里公式最多的一张
`产品图｜竞品链接｜竞品售价｜1688批发价｜运费｜包装｜平台扣点率｜单件利润(自动)｜24小时加购｜每日利润(自动)｜梯队(自动)｜同款竞品店铺数｜高粉竞品数｜低粉竞品数｜竞品总数(自动)｜首篇爆文距今(天)｜入场判断(自动)｜货源1-5｜结论`

```
单件利润 = 售价 - (批发价+运费+包装) - 售价×扣点率     ← 扣点率默认 5%，自己改
每日利润 = 单件利润 × 24小时加购
梯队     = ≥1万 第一 / ≥5000 第二 / ≥1000 第三 / 其余 不达标
竞品总数 = 高粉竞品数 + 低粉竞品数
入场判断 = 看「竞品总数」和「首篇爆文距今(天)」
```

**竞品怎么数**（P22）：

| 指标 | 定义 |
|---|---|
| 高粉竞品数 | 粉丝>2000，**或**该产品笔记数>1000 → 有账号权重，需要差异化手段 |
| 低粉竞品数 | 粉丝<500，**且**笔记数<500 → 和你同一起跑线，是**你能超越的对象** |
| 硬性要求 | 高粉+低粉 **总和不能大于 5 家** |

**入场判断的规则**（P22）：

| 情况 | 结论 |
|---|---|
| 竞品总数 > 5 家 | 放弃·生态位占满（中层生态位快占满了） |
| 首篇爆文 < 15 天 | 可以入场（不管有无低粉起来） |
| 首篇爆文 ≥ 30 天 且 有低粉起来 且 总数 ≤5 | 可以入场 |
| 首篇爆文 ≥ 30 天 且 没低粉起来 | 谨慎入场 |

> 「如果只有两三家，甚至只有一家，那这个市场还有空间，**值得冲**。」（P22）

> 黄色底 = 公式格，别手填。

## 第二步：筛爬词表

把 `4.8.xlsx` 拖到 `2-筛选爬词表.bat` 上。输出 `4.8_筛选结果.xlsx`。

**分档规则（严格照 SOP）**

| 档位 | 条件 | 颜色 | SOP 原话 |
|---|---|---|---|
| 低粉爆款 | 粉丝数 < 500 | 绿 | 最值得关注，说明产品本身能打 |
| 大爆款 | 24小时加购 > 800 | 红 | 头部玩家，看天花板 |
| 常规爆款 | 500 ≤ 粉丝 < 2000 且 加购 > 400 | 黄 | 市场腰部力量，需求稳定 |
| 未达标 | 其余 | 灰 | — |

结果按「低粉爆款 → 常规 → 大爆款 → 未达标」排序，同档内按加购降序。控制台最后会打印**低粉爆款 TOP 10**，就是你先点开的那 20 个链接的候选。

**列名认不出时**（表头跟前 3 行都不匹配）手动指定：

```bat
py filter_scrape.py 4.8.xlsx --map 粉丝=粉丝数,加购=24小时加购,店铺=店铺名
```

支持 `万/w/k` 单位（`1.2万` → 12000）。自动认的列：粉丝、加购、店铺、产品/标题、链接、销量。

## 第三步：从银河选品广场直接抓（可选）

双击 `3-选品广场.bat`，粘一次登录 token（F12 → Application → Local Storage → `mc_token`），
自动拉两批数据并按 SOP 分档上色：

- `选品广场-SOP分档.xlsx` —— 24h加购 > 400 的全部品，按低粉/常规/大爆/未达标分档
- `选品广场-低粉埋伏档.xlsx` —— 粉丝 < 500 且加购 1~400，热度还没起来的埋伏池

命令行直连（`py` 是 Windows 的 Python 启动器，本机没有 `python`）：

```bat
set MC_TOKEN=ses.xxxx
py fetch_plaza.py --min-cart 401
py fetch_plaza.py --max-followers 500 --min-cart 1 --max-cart 400 --limit 400
py fetch_plaza.py --segment growth          # 银河自己的「增长品」分层
```

支持的筛选项（对应接口参数名）：`--min-cart` `--max-cart` `--min-followers` `--max-followers`
`--min-price` `--max-price` `--category` `--segment` `--limit`

**接口说明**

| | 未登录 `/api/public/plaza` | 登录后 `/api/plaza` |
|---|---|---|
| 数据量 | 固定 20 条预览 | 16411 条，50/页 |
| 粉丝数 | ❌ 没有 | ✅ `shop_followers` |
| 24小时加购 | ⚠️ 取整到百位 | ✅ `add_cart_24h` 精确 |
| 筛选/排序 | ❌ 全被忽略 | ✅ 生效 |

所以**公开页选不出可买品**，必须带 token。

**可买性怎么判的**

银河三套预设标准全都带「到手价≥30」，脚本就拿它当门槛：

| 可买性 | 条件 |
|---|---|
| ✅ 可买 | `price >= 30` |
| ⚠️ 低价慎选 | `price < 30`（¥9.9 的品扣 5% 后单件利润只剩几毛） |
| ❓ 价格存疑 | `price_suspect = 1`，接口自己标的价格不可信 |
| 文案后缀 ·需券 | `deal_needs_coupon = 1`，要先去商品页领券 |

实测这三个字段的可用性（900+ 条采样）：

- `price_suspect` —— 有，但当前全站没有一条是 1，会全部落在 ✅/⚠️ 两档
- `deal_needs_coupon` / `original_price` —— 前端有渲染（表格里的「券」标记和划线原价），
  但 **接口不返回**，所有样本都是 null。脚本已按「有就用」接好，字段上线自动生效

对应的 xlsx 列：`价格标记`（原始标志：待核 / 需券）+ `可买性`（结论）。

### 银河的分层规则（比 SOP 细，可直接并进来）

| 银河分层 | 条件 | 对应 SOP 档位 |
|---|---|---|
| growth 增长品 | 加购≥400 且粉丝<500 | = 低粉爆款 |
| popular 热门品 | 加购≥400 且粉丝 500~2000 | = 常规爆款 |
| mature 成熟品 | 加购≥1000 | ≈ 大爆款（SOP 是 >800） |
| potential 潜力品 | 粉丝<500 且有销量 | SOP 没有，可作埋伏池 |
| premium 高客单蓝海 | 高单价+竞争小 | SOP 没有 |
| watch 观察 | 其余 | = 未达标 |

银河还多两个维度，建议并进 SOP 5.0：

1. **到手价 ≥ 30 元** —— 银河三套预设标准都带这一条。低于 30 元的品扣 5% 后单件利润只剩几毛，
   实测 767 个加购>400 的品里有 317 个（41%）卡在这。SOP 的调研表该加这个前置闸门。
2. **加购 ÷ 总销量**（需求新鲜度）—— 分子是现在想买的人，分母是已被吃掉的需求。比值越大越该先测。

## 第四步：赛道筛选（反着来，推荐先跑）

先看这一步的原因：从银河池子里按「需求新鲜」挑品，会持续撞 P22 的 ≤5 家 闸门 ——
银河只收录已经有 24h 加购的品，有加购就说明大店已经进来了。

实测例子：

| 品 | 竞品密度 | 结果 |
|---|---|---|
| 藤条香薰 | 高粉 **9** 家（VERBENA LINN 20.9万粉、宋朝 48.9万粉） | 放弃 |
| 生物酶浴室清洁剂 | 高粉 5 家（滴露、水卫士） | 放弃 |

所以**反过来筛**：先找大店还没占住的细分赛道，再从里面挑品。

```bat
py fetch_plaza.py --min-cart 101 -o 全站.xlsx          # 先拉一份宽的底库
py niche_scan.py all2.json --max-big 0 --min-small 2 --min-price 25
```

`niche_scan.py` 用 jieba 分词抽产品名词，按「高粉竞品 / 低粉竞品」分布聚类：

```
高粉竞品 = 粉丝 > 2000（或该产品笔记 > 1000）
低粉竞品 = 粉丝 < 500    ← 和你同一起跑线，它做成说明小号能做
中间地带 = 粉丝 500 ~ 2000
```

### 已跑出来的负面结论（不用重复调研）

「养发/护发」大类里，**只有「白发遮盖」小赛道是高粉 0**：

| 子赛道 | 条数 | 高粉 | 低粉 | 结论 |
|---|---|---|---|---|
| 白发遮盖 | 5 | **0** | 4 | ✅ 可做 |
| 养发液/精华 | 6 | 4 | 0 | ❌ 坐着头部的 5.1万粉大店 |
| 洗发水/饼/粉 | 8 | **7** | 0 | ❌ 苗菇子/木意/菁华全 |
| 假发片/补发片 | 6 | 4 | 1 | ❌ 天空树 40.7万粉 |
| 染发膏 | 2 | 2 | 0 | ❌ |
| 黄精/食补 | 3 | 2 | 1 | ❌ |

### 一个诚实的限制

银河只覆盖被跟踪的 16411 个品，所以「高粉 0 家」是**下限**，不代表赛道上真的一个大店都没有。
这个筛法的作用是**把「9 家高粉」那种必死赛道提前排掉**，剩下的还是得用小红书以图搜图确认。

## 附录 A：初选表「来源」怎么填

SOP 的三种初选方法，路径照抄：

**三种初选方法的细节**（P13~P16）：

1. **爬词表** — 用上面的脚本筛。一次点开 **20 个链接**，看完一个叉掉一个，只记店铺名
2. **千帆推广** — `chengfeng.xiaohongshu.com` → 创意分析 → 内容广场
   - 筛 `图文笔记 + 笔记支付金额 + 近7日` → 不搜关键词，直接往下翻到底
   - 再筛 `商品笔记/推广笔记 + 图文 + 阅读量`，必看**单品推荐**和**好物合集**两个题材
   - 关键词搜索：用小红书类目词 + 自己想搜的词 + 要**深耕**的产品词
   - 选图文不选视频的理由：视频不是主要拍摄形式，用图文去竞争打不过
3. **店铺榜单** — 千帆后台 → 数据中心 → 市场 → 笔记排名 → 成交榜 → 优秀账号 → 只看粉丝 <2000

**节奏**：每周一轮选品，约半天（P13）。

## 附录 B：SOP 里几条没进表格的硬规则

工具只做了筛选和记账，下面这些是策略层的，得自己记着。

### 1. 新手先做主动搜索型（P5~P7）

| | 主动搜索型 | 被动种草型 |
|---|---|---|
| 例子 | 牛肉丸、防漏尿垫、雪地靴清洁剂 | 星星人摆件、日落灯、解压玩具 |
| 驱动 | 刚需，有稳定搜索流量 | 颜值/情绪，热度 1-3 个月 |
| 拍照要求 | **不高**，拍清楚产品特点就行 | **极高**，构图、光线、氛围缺一不可 |
| 举例 | 手打的、肉质紧实、煮出来弹牙 | 拍得不够美，用户就没有想要的感觉 |
| 稳定性 | 可长期盈利 | 可能爆一个月就没了 |

> 新手优先主动搜索型：不用又要学运营又要练拍摄，心态不容易崩。
> 稳定出十几单、几十单之后，再去做被动种草型，「带着提升后的能力降维打击」。

### 2. 蓝海 / 红海的定义（P7）

```
蓝海：同款产品竞品 ≤5 家  /  产品关键词月搜索量 ≤5w  /  竞品总销量 ≤1w
红海：同款产品竞品 ≥5 家  /  产品关键词月搜索量 ≥20w
```

三个阶段对应的能力：

| 阶段 | 月销 | 要练的能力 |
|---|---|---|
| 一·蓝海品 | 5~10 万 | 抄爆款（抄到像，不是借鉴）+ 测试思维（不纠结，不情绪化） |
| 二·红海品 | 30~60 万 | 总结爆点并衍生（高铁半蹲 → 高铁站/坐/过道）+ 差异化（场景/元素/痛点/形式） |
| 三·月销百万 | — | 稳定店铺分 + 投流放大 + 笔记多样性（一天 7 篇，每篇不同类型） |

### 3. 测品节奏：每周只测一款（P23）

三周一轮，不并行：

| 周 | 干什么 |
|---|---|
| 第1周 | 周一~二 选 3~5 个可调研的品；周三前 下单竞品和货源样品 |
| 第2周 | 继续第二轮选品；周三~五 第一批样品到了，测品 |
| 第3周 | 周一 复盘第一轮（有反馈就进第二轮测试，没反馈直接淘汰）；继续测第二批 |

### 4. 测品结果的标准（P37）

```
第一轮：日均访客 > 40  或  出单     -> 进第二轮，不达标则淘汰
第二轮：每天稳定出单                -> 进店铺运营，不达标则淘汰
```

### 5. 投流只看保本 ROI（P32~P33, P42）

```
保本ROI > 6  利润太薄，不要投流（产品起来后靠自然流跑）
保本ROI > 4  利润一般，投流只为拉动新笔记爆文，不是为直接赚钱
保本ROI < 4  利润不错，可每日投流并放大预算
```

其它硬扣：

- 测品阶段每轮素材投 **200~300 元**，不是为了盈利，是**花钱买时间**（两三天拿到反馈）
- 日投流金额 **不超过每日平均销售额的 10%**
- 淘汰线：笔记花的钱 = 单件利润，ROI 还没到保本线就停掉
- 运营阶段淘汰线更严：**保本 ROI + 3**

> 三个阶段的本质都是**笔记连爆**。爆文权重有时效：运营不好半个月，正常 1~3 个月，运营能力强能到 6 个月。
> 延长靠**笔记多样性**（每篇触达不同人群），上限是账号的**活人感**（发故事、情绪、日常、吐槽）。

### 6. 货源怎么挑（P21）

先下单小红书竞品（对比完退货退款）→ 1688 & 拼多多以图搜图：

1. 优先**同发货省份**
2. 看**有标的商家**（实力商家 / 超级工厂 / 旗舰店）
3. 对比 **SKU 规格**（差太多基本不是同货源）

两个平台都找不到就不花精力了。**采购 3~5 家对比**，一家一种：

```
同省份的一家 ｜ 最低价的一家 ｜ 同SKU的一家 ｜ 实力商家的一家 ｜ 销量最多的一家
```

## 限制

- 只做**筛选和记账**，不碰千帆后台（那个要商家登录+扫码）
- 「补单晒图」环节不在范围内
- `filter_scrape.py` 对列名是模糊匹配，真表列名很怪的话用 `--map` 兜底
- 店铺名拿不到：银河 `/api/plaza` 不返回 `shop_name`，`fetch_plaza.py` 的输出里没有这一列
- 「笔记总数」「链接评价数」接口也给不了，二选表这两列得点开小红书商品页手抄
